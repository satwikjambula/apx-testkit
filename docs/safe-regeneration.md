# Safe regeneration

`apx-regenerate` is an opt-in, preview-first path for generated test files.
It does not change the legacy `apx-testgen`, watch mode, or onboarding writers.
Use it instead of those writers for a directory you want ownership-protected.
Mixing writers invalidates ownership hashes and may block subsequent regeneration.

```sh
apx-regenerate ./export --out ./generated-tests
# Review the JSON changes and copy its planHash into the apply command:
apx-regenerate ./export --out ./generated-tests --apply sha256:<hash-from-preview>
```

The library equivalents are `previewRegeneration` and `applyRegeneration` from
`@apx/testgen/regenerate`. Preview renders into a temporary directory, cleans it
up, and does not create or modify the destination. Invalid exports reject the
operation before any destination writes. The plan lists create, update, retire,
unchanged and conflict actions. Preview exits 1 for conflicts, 0 otherwise;
invalid CLI arguments exit 2. Apply errors exit 1.

## Ownership and conflict handling

`.apx-testgen-manifest.json` stores a versioned mapping of owned filenames to
their last generated SHA-256 hashes. Keep it with the generated files in version
control. Do not hand-edit it or delete it to bypass a conflict: it is the ownership
record, not an independently authenticated attestation.

- Unowned files at a generated destination block the entire apply, even if
  their bytes match. Existing output from the legacy generator is not silently
  adopted; start with a new directory, review the migration, and preserve your
  old customizations separately.
- Edited or manually deleted owned files block the entire apply. There is no
  force mode. Preserve custom behavior in separate files or resolve the edit
  explicitly before retrying.
- Unrelated files and subdirectories are untouched, including obsolete files
  carrying a legacy generated marker but absent from the ownership manifest.
- Retired owned files are moved to backup, not silently deleted. Replaced files
  and the old ownership manifest are backed up as well.
- Malformed manifests, unsafe ownership filenames, and non-regular targeted
  files (including symlinks) are rejected. The output directory itself and
  backup directory must not be symlinks.

The plan hash binds the resolved destination, ownership manifest, current bytes
of all affected files and desired generated bytes. Changes after preview require
a new preview. Unrelated custom files are not included because they are not
modified. Apply rechecks the plan after acquiring a cooperative exclusive lock.

## Backups, interruptions and concurrency

Apply returns a `backupDir` under `.apx-testgen-backups/<unique-id>` when it
changes output/ownership. Backups are never automatically pruned. They contain
the previous versions of displaced files and, when present, the old manifest;
an initial generation may create an empty backup directory. Unchanged regeneration
does not create another backup. Generated file bytes and the ownership manifest
are deterministic; backup directory names deliberately are not.

This is **not an atomic multi-file filesystem transaction**. An I/O failure can
leave a partially applied directory. The error reports the recovery backup.
Stop other writers, preserve a copy of the failed destination, and inspect the
old manifest and backups before restoring displaced files and the old manifest.
Review newly created files separately; backups are not a complete directory copy.
Do not blindly overwrite later manual changes during recovery.

`.apx-testgen.lock` excludes cooperating regeneration processes, not editors or
other generators. Keep the output directory idle during apply. A process killed
mid-apply may leave the lock: inspect and recover the output, confirm no writer is
running, then remove only that stale lock before previewing again.

No new Oracle runtime API or live-verification claim is introduced. This tool
protects generated files; it does not validate that their runtime assertions pass.
