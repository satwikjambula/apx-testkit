## Live coverage report — an honest result, including a real bug it surfaced

A real Playwright spec (`spike/tests/*.spec.ts`) was run against this app's
live instance with `APX_COVERAGE_LOG` set, then cross-referenced via
`apx-coverage`. The touch log correctly recorded the runtime static id the
spec actually used (see `ApexRegion.htmlDomId` / ADR-003 for why that
differs from the `.apx` export identifier for this app's region type).

**The coverage report below shows 0% touched anyway** — this is a real,
newly-discovered bug, not a broken test. `apx-coverage`
(`packages/generator/src/coverage.ts`) cross-references a recorded touch
against the AST by matching identifiers literally; it doesn't yet resolve
through `ApexRegion.htmlDomId` the way the runtime wrapper itself does. So
a touch recorded against the real runtime id doesn't match the export
identifier the coverage report looks for, and a genuinely-exercised region
is reported as untouched. This is being tracked as a follow-up, not fixed
here — reported honestly rather than omitted or faked clean.
